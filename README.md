# 打呼噜监测 App（SnoreTracker）

## 关于"能不能直接给你一个 apk"

老实说：不能，原因是我这边的沙盒环境网络被限制在几个白名单域名（GitHub、npm、pypi 这些），
访问不了 Google 的 Maven 仓库（`dl.google.com`）—— 而编译 Android 项目**必须**从那里下载
Android SDK 组件和 AndroidX 依赖库，我这边请求直接被拒绝（403），所以没法在这个环境里真的跑
`gradle build` 编出 apk。这不是我不想做，是这台机器物理上连不上那个仓库。

不过我确实找到了一个能绕开这个限制的办法：**用 GitHub Actions 在云端帮你编译**。GitHub 的服务器
不受我这边网络限制，能正常连 Google 仓库。整个项目我已经配好了自动构建流程，你只需要把代码传到
GitHub，等它自动编译完，直接在网页上下载 apk 装手机，全程不需要装 Android Studio、不需要懂代码。

---

## 方法一：GitHub Actions 云端编译（推荐，全程网页操作）

1. 注册/登录 [github.com](https://github.com)（免费）
2. 右上角 `+` → **New repository**，名字随便取（比如 `snore-tracker`），Public 或 Private 都行，
   不用勾选任何初始化选项，点 Create repository
3. 新建好的空仓库页面会有 "uploading an existing file" 的链接，点进去
4. 把这次给你的压缩包**解压后**，把里面所有文件和文件夹（`app/`、`.github/`、`build.gradle`、
   `settings.gradle` 等，注意包括名字以 `.` 开头的 `.github` 文件夹和 `.gitignore`，这些容易被
   系统隐藏，解压时留意一下）一起拖进网页上传框，拉到底点 **Commit changes**
5. 上传完成后点顶部 **Actions** 标签页，应该能看到一个叫 "Build APK" 的流程自动开始跑了（黄色圆圈
   在转 = 进行中，绿色勾 = 成功，一般 3-5 分钟）
6. 跑完后点进那次运行记录，页面最下方 **Artifacts** 里有个 `SnoreTracker-debug-apk`，点击下载，
   是个 zip，解压后里面就是 `app-debug.apk`
7. 把这个 apk 传到手机上（微信传文件给自己、发邮件、U盘都行），手机上点开安装。第一次装非应用商店
   来源的 apk，系统会提示"允许安装未知来源应用"，同意就行

这样装出来的是**调试版（debug）apk**，功能完全一样，唯一区别是没有用你自己的签名证书签名，
用的是自动生成的临时调试签名——自己装自己用完全没问题，只是不能拿去应用商店上架。

## 方法二：本地 Android Studio 编译（如果你想在电脑上改代码调试）

1. 装 [Android Studio](https://developer.android.com/studio)（免费）
2. 打开 Android Studio → **Open** → 选中解压后的 `SnoreTracker` 文件夹（不是里面的 app 子文件夹，
   是最外层那个），它会自动识别成一个完整项目并同步 Gradle（第一次要联网下载依赖，几分钟）
3. 同步完成后，用数据线连手机（提前在手机"开发者选项"里开 USB 调试），点绿色三角运行按钮，
   会直接装到手机上并打开

这个项目现在是标准的、完整的 Gradle 工程结构（不需要你手动新建项目再拷文件进去了，直接 Open 就是
完整可跑的工程）。

## 使用方式

1. 睡前打开 App，点"开始监测"，把手机放在床头（插着充电器）
2. 屏幕可以关闭，App 以前台服务持续监测，不会被系统杀掉
3. 早上点"停止监测"，首页会看到当晚记录，点进去看详细报告和每段打呼噜录音回放

## 功能说明

- 整晚持续录音分析（逐帧实时判断，不是间歇抽样）
- 检测依据：音量明显高于当前环境噪音基准（自适应）+ 声音偏低频（区分呼噜的沉闷声和说话/翻身的
  尖锐杂音），连续约0.5秒符合才算开始、连续约1秒不符合才算结束，避免抖动误判
- 每段打呼噜自动存一段 wav 录音（含检测前约1秒，不掐头）+ 一条数据库记录
- 首页看历史夜晚列表；详情页看总监测时长、打呼次数/总时长/占比、时间轴图、逐段回放

调参在 `app/src/main/java/com/snoretracker/app/SnoreAnalyzer.kt` 里，`loudMultiplier`
（灵敏度）、`zcrThreshold`（频率过滤严格程度）、`framesToStart/framesToStop`（判定所需时长）
这几个值可以按实际效果调整。

## 已知限制

- 经验性算法，不是医学级睡眠呼吸暂停(OSA)检测，不能替代专业睡眠监测或医生诊断
- 麦克风灵敏度、离床头距离、环境噪音（风扇、伴侣呼吸声）都会影响准确率，建议先试几晚看效果
- 整晚分析耗电，务必充电；录音片段存在 App 私有目录（卸载即清空），打呼噜频繁的话一晚可能攒
  几十到上百 MB，如需要可以在 `SnoreDetectionService.kt` 里加逻辑定期清理旧文件
- minSdk 设为 26（Android 8.0+），更早的系统装不了
- 如果 GitHub Actions 编译报错，把 Actions 页面里红色叉那一步的日志截图/文字发给我，我帮你看
